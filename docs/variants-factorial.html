SimdQuickHeap variants A1 to A9: factorial analysis

Goal: measure the effect of each SimdQuickHeap variant flag and find the best combination, separately for C++ and for Rust. The languages are never compared with each other. Each cell is the change in median time per operation when the term is on, as a 95% interval over passes. A screening design (32 runs, resolution IV) covered all nine flags plus a dummy bit that no code reads. A follow-up half fraction (32 runs, resolution VI) covered the six flags worth keeping. A sequential confirmation run tested the predicted best combinations against Opts 0.

C++ confirmation, measured against Opts 0

Seven sequential passes on CPU 3, nine Opts values in a shuffled order per pass. Opts 203 was not measured in the follow-up. It measured −20.8% [−21.1, −20.4] against a predicted −20.2%. Paired across passes, adding A4 to A1+A2+A6+A7 changes the overall time by −0.6% [−1.3, +0.1], adding A3 by +0.2% (not significant), and adding A5 by +7.5% (PushDecr +20.7%).

Rust confirmation, measured against Opts 0

Seven sequential passes on CPU 5. Opts 217 was not measured in the follow-up. It measured −29.8% [−30.3, −29.3] against a predicted −30.2%. Paired across passes, adding A5 to A1+A4+A6+A7 changes the overall time by −0.7% [−1.7, +0.4], with Monotone −3.5%, HeapSort −4.6% and PushDecr +7.3%. Adding A2 to A1+A4+A5+A6+A7 costs +0.6%.
